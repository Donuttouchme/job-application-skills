# Transferable evidence: a named class, not a new weight

A career changer's strongest evidence for the new field is proven work in another domain that served the same purpose (release discipline, threat analysis, code review as a gate). The old rules already counted "related but distant" work as weak, at half weight, but left it so vague that it was easily classed as missing, so nearly every DevOps posting fell out at the scout. We split it out as its own class, transferable, which must name the original domain and the shared purpose for each requirement. For the scout's must-have threshold it counts half, the same as weak, so nothing that passes today stops passing; in ranking, transferable outranks weak, because proven work beats a listed skill. In-progress items (certifications or projects under way) are never evidence, so the class cannot be used to claim what is still being learned.

## Considered Options

- **Lower the scout threshold for junior or career-change roles**: rejected; it admits postings without saying why they fit, where transferable evidence names the reason.
- **Drop weak to a quarter so transferable outweighs it**: rejected; it would silently reject postings that pass today, including ones carried by personal projects.
