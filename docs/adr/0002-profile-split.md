# Profile split into current truth, history and search constraints

The profile used to be append-only, so every correction sat next to the wrong text it replaced, and a writer had to work out each time which version still held. That is where inflated claims crept back in. We now correct the profile in place, with the user's confirmation, and move the old version and the reason to a separate profile history that writers never read; each permanent correction also leaves a one-line never-claim rule. Job-search logistics (commute, hours, licence, health parameters) move to search constraints, which the scout and the letter read and the CV never does.

## Considered Options

- **Keep append-only, mark superseded text**: rejected; it keeps the wrong version in the writer's context, which is the failure we are fixing.
